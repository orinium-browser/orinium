1//! Function-signature DSL for CSS math-function argument parsing.
2//!
3//! `parse_args!` declares a Rust-like signature as a bare identifier list,
4//! generates an argument-parsing closure from it, and immediately invokes
5//! it with the ambient bindings named by the signature. The signature
6//! lists the slot sequence (see [`munch!`](super::munch) for slot forms)
7//! and the body — an expression of type `Option<T>`.
8//!
9//! The head only names the bindings (`name`, `args`, `text_flow_style`,
10//! and any extra captures); their types and the return type are inferred
11//! from the ambient call, so call sites carry no type annotations.
12//!
13//! ```text
14//! parse_args! {
15//!     (<name>, <args>, <text_flow_style> [, <extra>]* [,])
16//!     { <ident>: <Type> [, ...] }          // slot list
17//!     => { <body> }                        // expression of type Option<T>
18//! }
19//! ```
20//!
21//! Slot types resolve through their [`ArgResolver`] impl (`CalcValue`,
22//! `f32`, `RoundingStrategy`, …), so the macro carries no per-type
23//! rules. The expansion yields `Result<T, ParseError>`; the call site's
24//! `report_parse_error` decides what gets logged.
25//!
26//! [`ArgResolver`]: super::args::ArgResolver
27
28macro_rules! parse_args {
29    // ── fixed or variadic slots, no unification ──
30    (
31        ($name:ident, $args:ident, $tfs:ident $(, $p:ident)* $(,)?)
32        { $($slots:tt)* }
33        => $body:tt
34    ) => {{
35        (|$name, $args, $tfs $(, $p)*| {
36            let mut __it = CssGroupCursor::new($args);
37            munch!(
38                [__it, $name, $tfs]
39                [$($slots)*] [plain $body]
40            )
41        })($name, $args, $tfs $(, $p)*)
42    }};
43}
