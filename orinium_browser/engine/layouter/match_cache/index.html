Epoch-scoped cache of CSS selector match results.

Selector matching is the dominant per-element cost after the rule set has been built: every layout run walks the candidate rules of every element and runs ComplexSelector::matches again, even though the result only depends on the (immutable) DOM snapshot and the (immutable) rule set. Repeated layout runs over an unchanged document — scroll, resize, hover and animation frames — therefore repeat exactly the same matches.

SelectorMatchCache memoizes (selector, element) pairs. The key is the identity of the ComplexSelector allocation (Arc::as_ptr) rather than the selector text: rules sharing a selector group share one Arc, so the pointer is stable for as long as the owning [RuleSet] is reused, and this avoids hashing selector trees on every lookup.

The caller owns invalidation. Entries are only valid for one DOM-snapshot/rule-set epoch, so SelectorMatchCache::clear must run whenever either input changes.
